建立 deterministic failure/repair evidence fixture dataset，验证原有分类、诊断、修复审计、Trace API 与 Viewer 的集成契约。fixture != production task；不声明采集成功率、修复率或系统效果提升。

代码基线：643220810ad1e648b36bf3c69b2fc6313df5d283（v0.5.4-freeze）。验证日期：2026-09-14，Asia/Shanghai。

数据集：[manifest.json](../tests/fixtures/failure_cases/manifest.json)。四个案例各 12 个文件：8 个原有 pipeline 产物、4 个测试元数据文件；共 48 个案例文件和一个 manifest。每个案例记录 id、source_type、generated_by、expected_artifacts、SHA256。manifest 另记录代码基线和生成器 hash。

生成器：[m55_failure_fixtures.py](../tests/helpers/m55_failure_fixtures.py)。从仓库根目录运行：


## Evidence generation boundary

原有 run_task、execute_with_bounded_repair、execute_plan、errors.classify、repair policy/proposer、RAG、脱敏摘要和产物序列化均被复用。execute_plan 外层仅记录调用 hash，随后委托原函数；不替代验证、采集或修复结果。

测试替身仅用于以下边界：

- Observation：固定合成输入，无真实浏览器观察。
- 初始规划：固定计划替身；第二次调用直接报错。report.model_calls=1 表示一次 planner stub 调用，不是云模型调用。实际云模型调用为零。
- HTTP：MockTransport 的固定 loopback GET 响应；默认同步/异步 HTTP transport 被阻断。
- network_error：在受控 HTTP transport 注入 PipelineError('network_error')，分类仍来自 errors.py；不验证真实 socket 故障到 taxonomy 的映射。
- Collector export：测试中关闭导出，三个 collector 结果标志均为 false，不宣称导出/比对通过。
- 时间：elapsed_seconds 固定为 0，events 时间为合成坐标；阶段顺序来自 run_task 回调，终态来自生成报告。这些不是测量数据。

inputs.json、task.json、events.json、telemetry.json 是测试元数据，不加入 ARTIFACT_NAMES、不注册到 artifact API、不修改生产 schema。输入只含合成 loopback 数据，无凭证。

## Safety checks

- unsafe_repair_rate：受限 duplicate_id/network_error 中违规应用 0/2；仅描述本数据集。
- second_llm_call：四案例均只有一次 planner stub 调用；无第二次规划，实际云调用为零。
- 原执行器调用数：unresolved=1、applied=2、duplicate_id=1、network_error=1。applied 的第二次是既有单次有界修复，不是新增行为。
- HTTP 请求数分别为 0、1、2、1；network_error 没有重复请求。
- RAG on/off 对照：每例 repair.json 和执行 telemetry 完全一致，诊断不影响执行或修复。
- 浏览器全部请求为 GET，诊断/修复区域没有操作按钮。刷新保持原终态；API 读取前后任务、事件、索引及文件 hash 不变。
- 四案例诊断内容不包含 URL；原始合成输入仅存在测试元数据中，不注册为可查看 artifact。
