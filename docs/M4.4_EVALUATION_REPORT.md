# Web Data Agent M4.4 Evaluation Report

Milestone: M4.4 Final Freeze

Baseline commit: `b800c7c` (feat(pipeline): bounded execution repair (M4.4.3))

## 1. Objective

Web Data Agent is an evidence-driven, bounded web data agent for local learning.
This report evaluates the M4.4 milestone: bounded deterministic repair.

The design principle of M4.4 is that the LLM proposes and deterministic code
validates and executes. Repair is not general self-healing. It is a closed,
policy-gated mechanism that can only act on a small, explicitly registered set
of error codes, only on already-observed evidence, and only within a bounded
attempt budget. Everything else fails closed.

## 2. Architecture

```text
User Task
   |
   v
Observation
   |
   v
Evidence
   |
   v
Retrieval
   |
   v
Planning
   |
   v
Validation
   |
   v
Execution
   |
   v
Verification
   |
   v
Bounded Repair
```

Bounded Repair wraps the execution stage. When execution fails with a
classified, repairable error, the deterministic repair module audits the
failure, may build a candidate plan from already-observed evidence, validates
the candidate with the same pre-flight validator the executor uses, and only
then may a bounded driver adopt it for a single additional execution.

## 4. Repair Policy

Policy is fail closed and derived from the deterministic error registry.

| Error | Proposal | Auto Apply |
|---|---|---|
| pointer_not_found | yes | yes |
| page_location_mismatch | yes | no |
| SECURITY | no | no |
| DATA_INTEGRITY | no | no |
| TRANSPORT | no | no |
| UNCLASSIFIED | no | no |

Notes:

- `pointer_not_found` is the only code on the automatic apply allowlist. A
  candidate is accepted only if exactly one relocated pointer matches the
  expected member kind; zero or multiple candidates fail closed.
- `page_location_mismatch` may yield a validated candidate proposal, but it is
  never applied automatically.
- A failure that may have begun collection, a missing original plan, or an
  exhausted attempt budget is rejected regardless of error code.
- Candidate generation reads only the original plan and observed evidence. It
  never calls the model, never re-observes the target, and never mutates the
  original plan.

## 5. Safety Guarantees

- max execution = 2 (the original plan plus at most one repaired plan)
- model_calls = 1 (no second LLM call for repair)
- no shell execution
- no arbitrary code execution
- no infinite retry
- no automatic security bypass
- repair audit is program-generated; no response values are persisted

## 7. Known Limitations

- pointer migration only inspects direct members of the observed response body;
  deeper structures are not migrated.
- collection_started is a conservative, phase-derived estimate, not a runtime
  signal.
- repair.json is best effort: if writing it fails, the already-determined
  failure classification is not changed.
- only one auto repair type is supported (`pointer_not_found`).
